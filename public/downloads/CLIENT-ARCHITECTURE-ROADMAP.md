# Sentinel 多端统一客户端能力规划

## 1. 决策摘要

采用“外部平台部署 Sentinel，Sentinel 管理自身安全内容”的双层模式：

1. Intune、其他 MDM、桌管、软件分发、配置管理或受控人工流程负责 Sentinel 的首次安装、二进制升级、卸载和紧急停用。
2. Sentinel Endpoint Agent 只从受认证 Collector 拉取已签名的策略、规则、恶意 Skill/MCP 指纹和 AI Coding 安全基线，并原子更新自己的受管内容。
3. Sentinel 不安装、不升级、不卸载 MDM、EDR、4A、NAC 或桌管客户端，也不成为通用远程执行工具。
4. Sentinel 可通过服务端适配器向 4A、EDR、SIEM/SOC、NAC 提交最小安全事件或待审批处置建议；影响账号、访问和终端状态的动作必须由外部控制面审批执行。

这一区分可以避免循环依赖：终端管理平台是软件生命周期根，Sentinel 是 AI Coding 安全策略执行点，Collector 是策略与审计控制面，4A 是身份和授权控制面。

## 2. 多端合一目标架构

统一逻辑核心负责策略验证、Agent 发现、Skill/MCP 解析、规则执行、报告归一化、签名验证和本地状态机。平台壳只承载操作系统差异：

| 层 | 统一能力 | Windows | macOS | Linux（后续） |
|---|---|---|---|---|
| 原生服务壳 | 安装、升级、调度、健康检查、受保护 IPC | Windows Service | LaunchDaemon + System Extension 预留 | systemd service |
| 统一安全核心 | 策略、基线、Skill/MCP、代码质量、报告 | 同一版本与规则语义 | 同一版本与规则语义 | 同一版本与规则语义 |
| 用户会话桥 | 发现用户级 AI Agent、最小权限写入基线 | 每用户 Helper/计划触发 | LaunchAgent/XPC Helper | user service |
| 本地存储 | LKG 策略、隔离区、队列、审计链 | ProgramData ACL | Application Support 权限 | /var/lib 权限 |
| 企业接口 | 统一身份、4A、EDR、SIEM、部署平台 | 服务端能力适配器 | 服务端能力适配器 | 服务端能力适配器 |

长期建议把 Python/PowerShell 扫描实现收敛为一个内存安全的共享核心（优先 Rust），通过稳定的本地协议向 Windows/macOS 原生壳暴露能力。迁移期间保持现有报告、策略和基线 Schema 不变，使用黄金样例确保新旧引擎结果一致。

## 3. 客户端完整能力域

### 生命周期与身份

- 设备注册、设备级密钥、证书或工作负载身份；不把人员密码存入终端配置。
- 首次安装、就地升级、降级拒绝、双槽回滚、卸载授权和紧急停用。
- 版本、策略、规则、基线和平台姿态证明；所有状态可由 Collector 审计。
- 安装包必须经过 Windows Authenticode、Apple Developer ID 与公证；企业发布同时校验 SHA-256 和发布清单。

### AI Agent 发现与基线注入

- 发现 Cursor、Claude Code、Codex、Windsurf、Gemini CLI、GitHub Copilot CLI、WorkBuddy、千问企业版、通义灵码、CodeBuddy，并通过可签名插件扩展目录支持新产品。
- 只解析声明过的配置和工作区，不执行被发现的 AI Agent、Skill 或 MCP。
- 用户级与仓库级基线使用受管标记增量写入，保留个人内容、ACL、所有者并拒绝符号链接/重解析点逃逸。
- 强制规则不能被用户界面、快速扫描或第三方配置关闭；例外必须带审批人、范围和到期时间。

### Skill/MCP 防护

- `allow / monitor / deny / unknown` 四态，`deny` 永远优先，未知项依据企业策略阻断或审计。
- 同时校验名称、发布者、签名、包摘要、配置指纹、命令路径、精确参数、传输、域名、文件范围、环境变量和权限声明。
- 下载或更新先进入隔离区，经过许可证、哈希、静态分析、提示注入、依赖、数据流和沙箱门禁后才能晋级。
- 高危对象可禁用其配置引用或移动至 Sentinel 自有隔离区；不得删除用户内容，恢复必须审计。

### 代码与数据安全

- 原生规则加可选 Semgrep/Gitleaks/Cisco 扫描器；第三方引擎不自动下载执行，必须独立签名、沙箱和版本固定。
- 默认本地扫描，上传最小发现摘要；源代码、Prompt、密钥和完整路径不离开终端。
- CPU、内存、磁盘、文件数、单文件大小、超时、并发和电量状态均有上限，交互式编码不被扫描拖垮。

### 运行保护与可观测性

- 进程最小权限、服务与用户桥分离、受限目录、私有队列、审计日志和防篡改状态。
- 离线继续执行最后已知有效策略；报告有界缓存，恢复联网后幂等补传。
- 本地诊断只输出脱敏健康信息；远程控制面不提供任意命令执行接口。
- 严重发现十五分钟内上报；策略漂移、Agent 漂移、基线未加载和扫描失效形成独立告警。

## 4. 推送机制与责任边界

| 对象 | 推荐发起方 | 机制 | Sentinel 权限 |
|---|---|---|---|
| Sentinel 首次安装 | MDM/桌管/软件分发 | MSI/PKG，设备级安装 | 不自举 |
| Sentinel 二进制升级 | MDM/桌管；后续可选受控自更新 | 签名包、灰度环、回滚 | 仅更新自身，默认由外部平台触发 |
| 安全策略与规则 | Sentinel Collector | HTTPS 拉取、摘要与签名、版本单调递增 | 自动应用通过门禁的自身内容 |
| AI Coding 基线 | Sentinel Agent | 从已验证策略包渲染到已发现 Agent | 仅写声明目标和受管块 |
| 恶意 Skill/MCP 情报 | Sentinel Collector | 增量签名清单、指纹、撤销列表 | deny 优先，隔离/禁用受审计 |
| 4A/EDR/NAC 动作 | 企业控制面 | 服务端适配器、审批工作流 | 只提交事件或建议，不直接执行不可逆动作 |
| Sentinel 紧急停用/卸载 | MDM/桌管/4A 审批后的运维流程 | 签名命令或软件生命周期任务 | 不允许普通用户远程触发 |

### 为什么不让 Sentinel 推送其他客户端

- 会让 Sentinel 获得通用软件分发和远程执行能力，显著扩大攻击面。
- Sentinel 一旦故障会同时影响 EDR、身份、桌管和自身恢复，形成控制面循环依赖。
- 企业已有软件资产、许可证、审批、维护窗口和回滚体系，Sentinel 不应复制这些职责。
- 未来 4A/MDM 厂商变化时，只替换服务端适配器和部署任务，不需要重构终端核心。

### 何时允许 Sentinel 自更新

只作为没有 MDM/桌管覆盖的受控终端补充路径。必须满足：企业显式开启、双签名验证、固定更新源、分阶段发布、维护窗口、双槽回滚、失败熔断、不可跳过紧急停用，并向 4A/审计平台记录完整证据。初始生产默认关闭。

## 5. 发布与更新状态机

`发现新版本 → 下载到隔离区 → 验证发布清单/双签名/平台签名 → 兼容性预检 → 等待发布环和维护窗口 → 原子切换 → 健康验证 → 成功确认`。

任一步失败进入 `保持 LKG + 上报`；健康验证失败进入 `自动回滚 + 熔断本版本`。规则、基线和二进制分别维护版本与回滚点，禁止一次更新同时跨越所有层而无法定位故障。

## 6. 分阶段路线

### P0：当前可验证试点

- MSI/PKG、小时扫描、策略热更新、LKG、离线队列、AI Agent 发现、基线注入、Skill/MCP/代码扫描。
- 完成试点包签名、真实 Windows/macOS 安装/升级/回滚/卸载验收。

### P1：统一客户端外壳

- Windows Service 与 macOS LaunchDaemon 原生壳、统一设备身份、健康 IPC、用户会话桥。
- 引入发布环、维护窗口、双槽更新和紧急停用；仍由外部部署平台负责二进制生命周期。

### P2：共享安全核心

- 将扫描、策略和报告核心迁移至共享内存安全实现；PowerShell/Python 退为兼容层。
- 对所有支持 AI Agent 建立配置解析契约、黄金样例和跨平台结果一致性门禁。

### P3：企业规模化控制面

- 多租户策略范围、例外审批、恶意 Skill/MCP 情报撤销、证书轮换、万级终端容量、审计留存和 SIEM/4A 联动。
- 按能力接入任意 MDM、4A、EDR、NAC；适配器失败不影响终端扫描。

### P4：受控自更新（可选）

- 仅为未受 MDM/桌管覆盖的设备启用 Sentinel 自更新；企业默认仍采用外部平台推送。

## 7. 不可变安全原则

- 单一 Sentinel Endpoint Agent，不捆绑第三方控制客户端。
- 基线强制加载，安全门禁不可由终端用户关闭。
- 恶意 Skill/MCP 默认禁止，未知对象按策略失败关闭。
- 不执行发现对象，不上传源代码和凭据，不提供任意远程命令。
- 二进制、策略、规则和基线全部签名、可审计、可回滚、可撤销。
- 身份、授权、审计和不可逆动作最终由企业统一身份/4A 控制面负责。
