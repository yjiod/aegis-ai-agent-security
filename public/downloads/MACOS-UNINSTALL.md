# macOS 卸载与状态保留

适用范围：包含 `aegis_macos_maintenance.py` 的系统 `.pkg` 候选安装包。
当前脚本维护工具需要系统 `/usr/bin/python3`；免 Python 的维护二进制尚未发布。
旧安装包缺少维护工具时会拒绝卸载，需要先修复安装。本文不代表安装包已经签名、公证或正式发布。

## 执行

在终端本地执行：

```sh
sudo '/Library/Application Support/AegisAgent/uninstall-aegis-macos.sh'
```

工具不接受参数，不读取上报令牌，不访问网络，不向外发送文件。
先确认卸载符合终端管理策略，并退出正在编辑个人 Agent 指令文件的编辑器。

## 处理顺序

1. 检查并停止系统级 `com.aegis.agent`、历史 `com.company.aegis-agent` 和 `com.aegis.execguard`。
2. 对 `/Users` 下非隐藏目录及 root 主目录，检查 GUI/user 域中的当前和历史 Agent 服务。
   主目录为符号链接时拒绝自动处理，避免跨目录误操作。
   停服后必须确认服务注册消失。未知状态、超时或权限错误不当作“已经停止”。
3. 仅删除八种工具个人配置中的一个完整 Aegis 受管块：Codex、Claude、WorkBuddy、
   Qwen Work、Gemini、Copilot、Lingma、CodeBuddy。保留块外字节、所有者、权限以及 Mac 元数据。
   标记缺失一半、重复或非独立行时拒绝修改该文件；符号链接、硬链接、特殊文件和超过 2 MiB 的文件也拒绝处理。
4. 将服务 plist、被系统安装禁用的用户 plist 和系统/用户运行目录移动到仅管理员可访问的
   `/Library/Application Support/AegisUninstallArchive/<批次>/`。不递归删除运行数据，不跨磁盘复制。
5. 每批保留 `status.json`，记录清理数量、归档数量及完成状态，不记录用户名、文件内容、令牌或原始路径。

## 返回值与恢复

退出码 `0`、状态 `uninstalled_with_retained_state` 表示上述卸载步骤完成且保留恢复资料。
退出码 `1` 表示未完成，可能已停止部分服务或清理部分受管块；不能当作自动回滚。
归档开始后的未完成批次保留 `partial` 状态。退出码 `2` 表示调用方式或权限不符合要求。

出现 `watch_cleanup_requires_verification` 表示守护进程曾无法确认扫描进程组退出。
此时 `watch-cleanup-pending.json` 会阻止继续扫描和卸载文件清理。管理员应先核对
实际进程、磁盘/挂载状态和服务日志，确认原扫描工作已结束后再处理标记并重试。
不要仅为让卸载返回成功而删除标记。

失败时保留终端和归档，按固定错误码排查。修复服务权限、损坏标记或磁盘问题后可重试。
不要手动批量删除运行目录，也不要把整个归档直接覆盖回用户配置。归档可能含原有入网凭据，
应按企业受限运维数据保管，不上传工单或代码仓库；归档保留期限由部署方的数据保留策略决定。

卸载不会自动恢复隔离的 Skill、被移除的 MCP 配置、执行权限或历史网络封禁，也不会修改仓库内规则文件。
这些属于独立的恢复/退役流程：先确认允许恢复的具体资源，再通过受信任客户端和审计流程恢复。
当前候选未提供自动恢复或服务器凭据吊销功能；客户端离线也不等于服务器端已经完成退役。

## 验证边界

回归使用合成目录验证失败路径、个人内容保留、元数据、状态归档和重复执行。
另外通过独立的 `/bin/sleep` launchd 服务验证实际进程启动、KeepAlive 服务退出和注册消失；
不操作现有 Aegis 服务。该证据不证明真实 Aegis 扫描子进程全部退出、生产卸载完成、
企业签名有效或隔离恢复成功，这些仍是发布验收项。
