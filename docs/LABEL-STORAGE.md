# 标签加载与存储验证

资产标签有四种独立命名空间：`skill`、`mcp`、`path`、`prefix`。数据库加载必须原样保留类型，文件或目录处置不能转为 Skill 处置。

## 加载行为

- 整个快照通过类型验证后才写入内存。未知类型使本次加载失败，返回固定错误 `labels_load_failed`，不会把部分快照留在内存。
- 数据库返回失败或抛出异常时不缓存成功状态，下一次调用可以重试。成功加载的空快照可以缓存。
- 同一模块内的并发加载共用一次请求。读取快照期间发生的本地修改和删除优先于旧快照，包括内存中尚不存在的条目的删除。
- 只在加载期间跟踪修改键，加载完成或失败后释放该记录。

加载一致性与拒绝优先规则分别验证。跨实例缓存一致性和写入事务另行验证，不因本修复声称已完成。

## 告警过滤的封禁优先级

过滤发现时，当前精确 `deny` 优先于允许快照；路径发现的任意匹配父目录 `deny` 优先于精确或更深层目录 `allow`。必须检查全部适用父目录后才能抑制，不能在遇到第一个允许项时提前返回。目录边界不扩展到同名前缀的兄弟目录，也不替代 Skill/MCP 的独立身份。

管理员 API 接受已归一化的合法 `prefix` 规则，根目录及无尾斜杠的模糊输入继续拒绝。路径类型识别使用去掉行列号后的归一化键，行号改变不会绕过路径规则。

这修正的是控制台发现、工单和设备发现共用的过滤规则，不证明终端实际阻断，也不等同于分类＋片段指纹的持久去重；后者按[产品硬约束](PRODUCT-REQUIREMENTS.md)单独实现。终端执行开关保持原值。

## 加载失败门禁

标签查询、增改、删除、默认条目录入、策略预览和策略发布在无法加载标签时返回 HTTP 503，固定错误码 `labels_unavailable`，响应禁止缓存。自动纠偏不拉取发现、不写规则、不发布或通知，返回 `ran=false`、`reason=labels_unavailable`；手动触发该扫描的 API 同样返回 HTTP 503。

每次失败门禁记录 `labels:load_failed` 审计，包含操作类型，不包含数据库异常原文。鉴权仍在加载之前执行；恢复数据库后请求可以重试。已签名策略的读取与只读发现展示沿用原有路径，此变更不改写现有发布件。

## 部署与验收

控制台代码通过 CI 和人工评审后按既有流程发布，端点无需升级。使用隔离数据库分别保存四种类型后重启控制台，核对类型、目录边界和人工处置；模拟数据库中断后恢复，验证重新加载；并发修改或删除时验证旧快照不能覆盖新操作。生产数据库和真实设备信息不用于自动化测试。

本次测试运行真实标签模块，用合成数据库边界覆盖类型保留、目录边界、返回失败、异常、无效快照、并发修改/删除和空快照缓存。macOS/Windows 共用控制台状态；端点执行行为仍需独立验收。

回滚仅涉及控制台版本，无数据库迁移。回滚会恢复旧的加载语义，应保留修复后的测试证据供评审决策。
