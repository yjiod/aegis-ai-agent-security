# 标签加载与存储验证

资产标签有四种独立命名空间：`skill`、`mcp`、`path`、`prefix`。数据库加载必须原样保留类型，文件或目录处置不能转为 Skill 处置。

## 加载行为

- 整个快照通过类型验证后才写入内存。未知类型使本次加载失败，返回固定错误 `labels_load_failed`，不会把部分快照留在内存。
- 数据库返回失败或抛出异常时不缓存成功状态，下一次调用可以重试。成功加载的空快照可以缓存。
- 同一模块内的并发加载共用一次请求。读取快照期间发生的本地修改和删除优先于旧快照，包括内存中尚不存在的条目的删除。
- 只在加载期间跟踪修改键，加载完成或失败后释放该记录。

加载一致性与拒绝优先规则分别验证。跨实例缓存刷新另行验证；写入提交确认及数据库条件更新见下文。

## 告警过滤的封禁优先级

过滤发现时，当前精确 `deny` 优先于允许快照；路径发现的任意匹配父目录 `deny` 优先于精确或更深层目录 `allow`。必须检查全部适用父目录后才能抑制，不能在遇到第一个允许项时提前返回。目录边界不扩展到同名前缀的兄弟目录，也不替代 Skill/MCP 的独立身份。

管理员 API 接受已归一化的合法 `prefix` 规则，根目录及无尾斜杠的模糊输入继续拒绝。`path` 的新增和删除使用与发现匹配相同的归一化键，类型识别也使用去掉行列号后的键，行号改变不会绕过路径规则。既有未归一化存量记录不在本次迁移范围，需要单独盘点处理。

这修正的是控制台发现、工单和设备发现共用的过滤规则，不证明终端实际阻断，也不等同于分类＋片段指纹的持久去重；后者按[产品硬约束](PRODUCT-REQUIREMENTS.md)单独实现。终端执行开关保持原值。

## 加载失败门禁

标签查询、增改、删除、默认条目录入、策略预览和策略发布在无法加载标签时返回 HTTP 503，固定错误码 `labels_unavailable`，响应禁止缓存。自动纠偏不拉取发现、不写规则、不发布或通知，返回 `ran=false`、`reason=labels_unavailable`；手动触发该扫描的 API 同样返回 HTTP 503。

每次失败门禁记录 `labels:load_failed` 审计，包含操作类型，不包含数据库异常原文。鉴权仍在加载之前执行；恢复数据库后请求可以重试。已签名策略的读取与只读发现展示沿用原有路径，此变更不改写现有发布件。

## 部署与验收

控制台代码通过 CI 和人工评审后按既有流程发布，端点无需升级。使用隔离数据库分别保存四种类型后重启控制台，核对类型、目录边界和人工处置；模拟数据库中断后恢复，验证重新加载；并发修改或删除时验证旧快照不能覆盖新操作。生产数据库和真实设备信息不用于自动化测试。

本次测试运行真实标签模块，用合成数据库边界覆盖类型保留、目录边界、返回失败、异常、无效快照、并发修改/删除和空快照缓存。macOS/Windows 共用控制台状态；端点执行行为仍需独立验收。

## 处置来源与升级

`decision_source` 由服务端写入，值为 `manual`、`preset`、`automatic`、`legacy`。
默认目录录入为 preset，自动封禁写入为 automatic，管理员显式提交 disposition 为 manual。
只修改标签或备注不改变原处置来源；API 拒绝客户端提供 decision_source。标签内容、
操作者名字或恰好出现在目录中的资产名都不能证明处置来源，更不能证明发布者身份。

Skill/MCP 的 preset、automatic 或来源不明的 legacy 允许项仅抑制相应 unknown_skill /
unknown_mcp 接入提示；其他风险保留在聚合发现、设备发现和自动工单中。明确 manual
允许暂时保留既有资产级例外语义，path/prefix 也沿用既有规则；这仍不是片段级例外。
当前精确封禁及适用目录封禁仍优先。自动纠偏冲突携带来源，不把预置允许显示为人工
裁决；本批没有因为新增来源字段就提高规则置信度或扩大自动封禁范围。

部署前先在隔离 PostgreSQL 验证并应用 `migrations/0008_label_decision_source.sql`，
再发布全部标签读写进程。迁移只增加列，既有记录统一为 legacy，不根据可编辑标签猜测
历史决定。缺少该列时新版本加载失败并由既有门禁返回 503，不回退为过宽的允许状态。
避免新旧写进程混用；旧写进程不知道此字段，不能维护来源。保留原记录与审计，用明确
的人工确认或可验证的目录迁移重建来源；重跑 seed 不会覆盖既有处置。

升级后 legacy Skill/MCP 的内容风险可能重新出现。这是缺少历史来源的兼容性影响，
应在试点前核对，而不是批量认定历史记录全为人工例外。控制台明确标记历史来源待核对。

回滚可保留新增列，不能删除历史决定；旧版会恢复宽泛抑制语义，因此不是无风险回退。
本地自动测试覆盖真实处理函数及合成存储边界，不声称已在生产数据库完成迁移。

已知后续项：跨实例缓存刷新、可信目录发布者/版本绑定，以及分类与片段指纹例外仍需分别完成。预置来源本身不是可信供应链证明。


## 写入提交确认

配置 PostgreSQL 时，人工更新、删除、预置录入及自动封禁都等待数据库确认；成功后才
更新进程内快照。失败响应为 503 `labels_write_unconfirmed`，不会返回底层异常或记录
成功审计。数据库连接或 COMMIT 确认丢失时无法断言已回滚，因此使用“未确认”措辞。
自动纠偏遇到未确认写入不发布策略、不发送本轮处置通知，不将未确认的规则记为已保存。

同一进程内的写入排队执行，失败不堵住后续重试。未确认写入使当前允许快照失效；
即使调用方还持有旧允许集合，也不能继续抑制风险。下一次成功加载用数据库完整快照
替换旧数据，包括移除数据库已不存在的键。跨越未确认写入的旧在途加载被丢弃。
删除会实际访问数据库，不因本进程没有缓存该键就跳过。

数据库更新采用补丁语义：仅改备注/标签不会用过期缓存覆盖当前 disposition 或来源。
预置录入与自动封禁只填充未处置条目，条件在 SQL 冲突更新中再次校验；并发人工封禁
不会被预置允许覆盖。批量按稳定键顺序获取锁，整批提交或回滚；返回实际保存的条目和
被保留的权威条目，进程据此更新快照及统计。它仍不替代跨实例缓存刷新或完整策略发布事务。

未配置 PostgreSQL 的开发模式保持进程内临时状态，不保证重启后保留，不能作为生产持久化
验收证据。本批没有引入新的数据库迁移，在来源字段迁移 0008 的基础上更新读写行为。

测试包含实际 API 的等待提交、写入/删除失败、确认丢失、重试、过期加载、并发写入及
自动纠偏不误发布；隔离 PostgreSQL 测试验证补丁更新、条件更新、独立连接竞争和实际删除。
提交确认丢失用故障边界模拟，不宣称已完成数据库主备切换或跨节点故障演练。
