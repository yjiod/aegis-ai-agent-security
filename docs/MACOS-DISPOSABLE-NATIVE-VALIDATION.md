# macOS 一次性系统路径原生维护验证

此门禁运行于 GitHub 托管的 ARM64、Intel Mac 临时机器，由原生构建工作流显式启用。正常本地测试在访问系统路径之前跳过；不得在开发、试点或生产终端启用。若固定安装目录、两个已知服务或对应 plist 已存在，门禁失败，不将已有安装当作测试夹具。

## 实际验证范围

测试把本次 CI 构建的冻结客户端放入真实 `/Library/Application Support/AegisAgent`，编译只休眠的旧程序，并用真实 launchd 注册两个已知系统服务。客户端运行未经重定向、未替换工具的维护 CLI：

- 原生 `--stage-native-runtime` 停止两个服务；检查旧进程实际退出、旧打开文件描述符保持原字节、新程序摘要及私有备份。
- 未注册服务时确认操作必须失败；相同候选重复安装仍保留最初备份。
- 原生恢复原子写回旧字节，服务保持未注册，状态为 `restored_activation_pending`。
- 再次安装，注册只运行内存自检的原生任务并确认注册；诊断不能声称上报或扫描健康。
- 再恢复，验证服务移除及旧字节，并清理仅本测试排他创建的 plist 和目录。清理失败也使门禁失败。

客户端进程受独立沙箱限制：禁止网络及用户目录读取，只允许候选程序与系统 launchctl 两个可执行文件；系统及常见外部 Python 目录也被禁止读取。测试实际尝试执行另一个程序及系统 Python 并验证被拒。客户端 PATH、PYTHONHOME、PYTHONPATH 指向不存在的位置。测试编排与编译仍使用 CI 工具链，不属于终端运行时。

每个架构上传 `aegis.disposable-native-maintenance/v1` JSON，记录候选摘要、架构、版本和验证范围，不含用户身份、凭据、进程列表、文件片段或真实终端数据。证据上传发生在测试和清理成功后。

## 不构成的证据

这不是完整 Installer 安装，也没有执行真实扫描、入网、策略注入、用户通知、控制台上报、全链路升级、签名公证或整个包回滚。临时 CI Mac 自带构建用 Python；沙箱禁止客户端使用它，不等于机器上物理不存在 Python。完整干净终端生命周期和多工具试点仍需独立验收。
