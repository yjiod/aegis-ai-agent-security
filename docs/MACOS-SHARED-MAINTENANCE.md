# macOS 系统维护共同锁与中断状态

状态：开发候选。维护模块随原生客户端内嵌；终端无需安装 Python。

## 已接入的操作

支持本协议的客户端对系统 canonical 主程序使用同一把非阻塞排他锁：

- 安装后的主程序 stage、注册确认 confirm、旧主程序 restore；原有操作内部的保护锁保留。
- 系统卸载：从首次停服到基线清理、归档和最终状态写入，均在锁内。
- 系统主程序自动更新：在获取清单之前获取锁，持有到下载、预检、应用、应用后核验和更新回执写入完成。回执写入失败仍报告程序已经更新，同时标记回执不可用。

锁位于安装目录的父目录，文件名 `.aegis-system-lifecycle.lock`，不会随 `AegisAgent` 目录归档而改变。另有 `.aegis-system-lifecycle.json` 记录维护状态。两者只允许管理员拥有的私有普通文件，无符号链接、多硬链接或扩展 ACL；父目录也必须受保护。竞争失败返回 `maintenance_busy`，不继续联网、停服或改程序。

## 状态及恢复

| 状态 | 含义 | 自动更新 |
|---|---|---|
| 无记录 | 旧安装；仍校验安装目录、旧激活记录及清理标记 | 满足其他条件才允许 |
| `installing` | 已开始主程序安装，尚未确认注册 | 拒绝 |
| `ready` | 注册确认已完成；实际健康仍独立判断 | 满足其他条件才允许 |
| `recovery_pending` | 正在或已恢复旧主程序，待完成激活 | 拒绝 |
| `uninstalling` | 已开始卸载；失败时保留此状态 | 拒绝 |
| `uninstalled` | 卸载完成，等待新的批准安装 | 拒绝 |

安装成功 stage 后仍保持 `installing`，只有原生 confirm 校验通过才变为 `ready`。自动更新同时检查旧版 `native-runtime-activation.json`，不能因共同状态不存在而忽略旧的未完成激活记录。未知或不可读记录、待核实清理标记、已消失的安装目录均拒绝自动更新，不自行重建客户端。

中断卸载只允许继续完成卸载，不允许安装或恢复操作越过 `uninstalling`。完成卸载后，可以重新部署批准安装包；stage 会进入新的 `installing`。旧主程序恢复后，应按原生恢复手册完成批准包修复和健康核验。不要删除锁文件、状态文件或激活记录来强行解锁；运行中的锁由系统在进程退出后释放，状态则需要相应维护流程完成。

诊断把未完成或不可读的共同状态标为不健康。`ready` 不等于进程、扫描或上报已经健康。状态记录仅用于本机协调，不是不可篡改的中心审计或发布者签名证明。

## 验证及边界

合成文件测试覆盖跨进程争锁、目录移动和重建后仍使用同一把锁、更新在联网前拒绝、回执期间继续互斥、中断卸载与重新安装、旧激活记录、清理标记、链接/权限异常及诊断。一次性 CI 系统路径测试进一步让真实冻结客户端与另一个进程竞争共同锁。

锁保护以上原生维护操作，不覆盖 Installer 在 postinstall 前写入 payload 的阶段，也不强制约束旧客户端或外部 root 程序。用户服务退役、独立旧服务迁移和其他配置操作尚未统一到整个生命周期事务。下一步需要安装入口协调、安装前快照及跨整个 Installer 的事务恢复；不能据此宣布完整安装/更新/卸载事务已经完成。
