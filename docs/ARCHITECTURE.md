# 架构与信任边界

## 数据流

1. 企业 MDM、软件分发系统或受控本地流程以 SYSTEM/root 安装经过 SHA-256 固定的 Agent、策略和编码基线；Intune 只是可选实现。
2. 周期任务通过文件系统标记发现 AI Coding 工具，不执行被发现的二进制。
3. Agent 从同一受认证 Collector 拉取已审核策略，校验 HTTPS、SHA-256、Schema 与版本单调性后原子更新；失败则保留 last-known-good。
4. Agent 自动同步带托管标记的基线，扫描 Skill、MCP、代码和依赖清单。
5. 报告原子写入受限目录；配置上报后，以 Bearer 与 HMAC 发送到 Collector，失败则进入有界离线队列。
6. Collector 严格验证报告契约、签名、时钟窗口和大小，将规范化报告写入 SQLite WAL。
7. Adapter Worker 从 Collector 的已验证报告生成最小事件，以派发账本、稳定幂等键和有界失败队列连接标准企业 4A、安全 Webhook及可选的深信服/联软兼容适配器；各目标相互隔离。
8. 私有控制台通过同源服务端代理读取 Collector 聚合摘要，浏览器无法取得 Collector 令牌。

## 信任边界

- **终端不可信输入**：项目文件、Skill、MCP 配置、依赖清单和用户规则。解析必须有大小/数量边界，不执行内容，不跟随越界链接。
- **终端管理边界**：部署系统负责脚本身份、文件分发和设备分组。核心包不依赖特定 MDM；哈希固定、脚本签名、最小权限与分阶段分配仍是生产要求。
- **报告边界**：报告只包含脱敏路径和受限证据。Collector 验证发现项与汇总计数一致。
- **规则供应链边界**：第三方版本只进入隔离状态。上游程序和 MCP Server 不在终端自动执行；许可证、摘要、回归和沙箱门禁通过后，才能发布为企业策略或固定版本可选引擎。
- **4A 与厂商边界**：终端永不直连 4A、EDR 或桌管管理面。Adapter 只允许精确 HTTPS 主机，令牌从受保护环境注入；标准 4A 事件只提出观察、告警或待审批动作，不直接执行封禁。深信服/联软启用时仍要求独立验收证据。
- **控制台边界**：Sites 为私有站点。摘要与最多 200 台终端姿态通过只读代理展示；代理限制目标、超时、响应大小、UTF-8、时效与返回字段。任务下发 API 尚未实现。

## 失败模式

- 策略损坏：Python 保留 last-known-good；Windows 报告高危状态。
- 网络中断：报告与厂商事件进入权限受限、有界、可隔离损坏项的队列。
- Collector 异常：健康检查与 API 返回 503，不伪装为客户端错误。
- 报告或版本漂移：终端管理平台合规失败，Collector 摘要显示版本姿态。
- 回滚校验失败：周期任务保持停止，Intune 检测进入修复态。

## 客户环境验收项

- 企业 4A 的 HTTPS 接收地址、服务身份、Bearer 令牌轮换、租户标识及审计留存策略。
- 选定终端管理平台的试点组、脚本签名和凭据注入；如选用 Intune，可复用包内现有制品。
- 如启用，深信服 EDR 与联软具体版本的正式 API 路径、鉴权和字段映射。
- Collector 企业 TLS/mTLS、反向代理、备份与监控。
- 控制台到客户 Collector 的私有网络通道和只读服务账号。
