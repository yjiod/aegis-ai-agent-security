# macOS 主程序替换与安装中断恢复

状态：开发候选。所有维护命令均由自包含原生客户端执行，终端不需要安装 Python。ARM64 和 Intel x64 构建分别验证；测试中的构建解释器不是终端依赖。

## 安装行为

系统安装包先验证候选主程序并处理旧用户服务，再调用 `--stage-native-runtime`：

1. 校验固定系统目录、候选文件及包内清单；常规文件必须无链接、单硬链接、所有者正确、不可被其他用户写入、无扩展 ACL，读取有大小和一致性限制。
2. 独占维护锁，写入仅 root 可读的 `native-runtime-activation.json`。记录候选版本及新旧 SHA-256，不记录身份、凭据或扫描片段。
3. 确认两个已知系统 Agent 服务已移除，并拒绝待核实的 watch 清理标记。停止失败时保留原主程序和未完成记录。
4. 将旧主程序保存为权限 0600 的 `.native-runtime-previous`；使用同目录临时文件、文件同步、原子替换和目录同步安装新主程序。原来已经打开的文件描述符仍指向完整旧文件。
5. 完成原有入网流程并注册 launchd。注册失败直接使安装失败；成功后 `--confirm-native-runtime` 核对候选、主程序、注册状态及旧服务缺席，再将记录更新为 `service_registered`。

`service_registered` 只表示注册已确认，输出始终为 `health_verified:false`。健康仍需检查实际运行、完整性、新鲜扫描和成功上报。未完成或不可读取的激活记录会使健康检查失败。已有旧版安装没有此可选记录时保持原有检查行为。

不再递归修改整个安装目录的所有者，也不忽略旧 Agent 服务停止错误。可选 ES 执行守护仍走独立安装逻辑，不在此次主程序事务范围内。

## 中断与恢复

- `preparing` / `staged`：可重新运行同一批准安装包。只有当前主程序、候选版本、候选摘要和必要备份均匹配记录时才继续。替换后、检查点前中断也遵循这些条件。
- `restoring`：先重复完成主程序恢复，不自动进入新安装。
- 同一候选已注册后的重复安装保留首次备份；下一次不同候选安装只保留其前一主程序。
- 未完成安装不接受另一个候选。先恢复或完成原候选，随后按批准包流程安装其他版本；不删除记录来绕过一致性检查。

有有效旧主程序备份时，管理员可使用系统目录中本次批准包的架构二进制：

```sh
# ARM64；Intel 改用 aegis-agent-darwin-x64
sudo "/Library/Application Support/AegisAgent/aegis-agent-darwin-arm64" --restore-native-runtime
```

该命令校验当前主程序和备份摘要，确认服务停止，再原子恢复旧主程序，留下 `restored_activation_pending`。它不会启动旧服务，也不会读取或恢复凭据、策略、旧用户服务、原包内其他文件或 daemon plist。空文件等旧损坏主程序可以被保留并修复；恢复只保证原字节，不能保证其可执行。新装没有旧主程序时明确拒绝。当前主程序发生记录外变化、备份损坏、ACL/权限异常时拒绝并保留现场。

恢复后需选择兼容的批准安装包完成修复，并独立验证健康。不要仅启动旧二进制并宣称整个包已回滚。签名、公证、发布者和整包摘要校验仍由批准包入口负责；本地摘要清单不是发布者认证。

## 验证边界与后续工作

隔离测试使用合成字节和模拟服务，覆盖停止失败、原子替换、中断恢复、重复安装、符号/硬链接、FIFO、可写文件、维护锁、候选/备份篡改、旧服务再出现和健康误报。原生构建验证模块实际内嵌。安装包测试明确替换固定生产路径的激活调用，继续验证真实打包、架构选择和嵌入式入网；不是完整特权安装证据。

待补：安装包落盘前完整快照、跨整个安装与自更新/卸载的共同互斥、真实干净双架构终端安装升级、实际服务启动及子进程退出证明、签名公证与整包恢复演练。安装器在 postinstall 前已经写入架构文件、工厂策略、基线及 plist，因此这里的主程序备份不具备完整包回滚语义。锁只覆盖每个维护调用；不能据此宣称已消除所有 root 并发操作竞态。
