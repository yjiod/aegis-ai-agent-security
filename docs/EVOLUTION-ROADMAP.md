## 二、开源选型清单（供你验证，第 3、4 条）

### 准入 / NAC（网络准入控制）
- **PacketFence（首选）**：自托管、社区活跃、企业级 NAC，支持 802.1X/Portal/设备指纹/隔离 VLAN，可与现有 4A 账号源对接。
- 备选：OpenNAC、Gatekeeper（轻量自托管）。
- 验证点：能否用你的 4A 账号做准入认证；能否按"终端是否装 Aegis + 是否合规"决定放行/隔离。

### EDR（终端检测与响应）
- **Wazuh（首选）**：自托管 SIEM+EDR 一体，agent 跨平台，规则/告警/响应齐全，社区大。
- **osquery + Fleet（ telemetry 层）**：osquery 做终端实时查询/Inventory，Fleet 做管理与下发；适合"查终端状态"而非重告警。
- **Velociraptor**：偏取证/深度响应，作为补充。
- 验证点：agent 资源占用；告警能否回传 Aegis 控制台统一展示；响应动作能否受 Aegis 策略约束。

### 桌管 / 推送管控（MDM）
- **Fleet（首选）**：开源 MDM + osquery + 补丁管理，跨 macOS/Windows/Linux，支持脚本/配置下发。
- 备选：MicroMDM / NanoMDM（Apple MDM 协议栈）、myMDM。
- 验证点：能否向已装 Aegis 的终端推送策略/脚本；Windows 侧 MDM 通道是否可用。

### 代码质量 / SAST（Fortify 之外）
- **Semgrep**：规则即代码、快、CI 友好，适合自定义基线落地。
- **CodeQL**：深度污点/数据流分析，适合"深度"扫描模式。
- 语言专项：Bandit(Python)、gosec(Go)、SpotBugs+FindSecBugs(Java)、ESLint-plugin-security(JS/TS)、Brakeman(Ruby)、ShellCheck(Shell)。
- 依赖/密钥/IaC：**Trivy**（依赖+IaC+密钥）、**Gitleaks**（密钥）。
- **AI 增强**：Semgrep/CodeQL 结果 + LLM 误报分诊；AI PR 安全审查（Codex/Gemini/Claude 作为"AI 审查"扫描模式）。
- 验证点：误报率、速度、能否输出统一 findings 格式回传 Aegis。

### 扫描模式（用户可选，第 4 条）
- **快速**：密钥 + 依赖（Gitleaks+Trivy），秒级。
- **标准**：+ 核心 SAST（Semgrep），分钟级。
- **深度**：+ CodeQL 污点 + AI 审查，较慢。
- **自定义**：用户导入的基线规则集。

## 二·五、厂商中立硬约束（贯穿所有集成）

**开源产品只是"产品验证期 / 过渡期"的参考适配器，绝不是绑定路线。** 必须遵守：

- 所有外部能力（准入 NAC / EDR / 桌管 MDM / 4A）一律经**既有厂商中立契约** `aegis_4a_interface.py` 的 `FourAInterface`（Protocol + `FourACapability` 枚举）接入；控制台与 adapter worker **只依赖该契约**，不依赖任何具体产品的 SDK/接口。
- 现网商用 EDR / 桌管 / NAC 与过渡期开源（PacketFence/Wazuh/Fleet）**都是该契约的一个适配器实现**，地位对等、可互相替换；未来引入任何新 4A/安全产品，只需新写一个适配器实现同一契约，**核心代码零改动**。
- 禁止在核心逻辑/策略/控制台里写死任何厂商 endpoint、字段名或认证方式；厂商差异全部封装在各自适配器内，经 `aegis-vendor-contracts.json` 声明传输与凭据边界。
- 选型变更（开源→商用、或商用换厂商）只影响"启用哪个适配器"的配置，不影响数据模型与下发通道。

## 三、"只推一个端"架构（第 6 条，修订版）

**推送/分发归桌管，Aegis 不负责安装任何别的组件。** 正确分层：

- **分发层 = 桌管 / MDM**（现网商用桌管 / MDM，或开源 Fleet）：把 Aegis bundle 当作普通受管软件**静默推送到终端**；Aegis 新版本也优先由桌管推送（企业主通道）。这是桌管的本职（软件分发/补丁），不应由 Aegis 代劳。
- **终端层 = 仅新增 Aegis 一个 Agent**：员工端只多这一个 AI 安全 Agent（发现/扫描/上报/策略执行；无桌管环境用自更新兜底）。EDR / NAC / 桌管 **不作为额外可见 agent 推给员工**。
- **集成层 = 服务端 / 控制面对接（不在终端安装）**：
  - **EDR**（现网商用 EDR / 开源 Wazuh）：server-to-server API 拉告警与资产，与 AI-Agent 风险关联研判；Aegis 不安装 EDR。
  - **NAC**（PacketFence）：Aegis 把终端合规姿态经 4A/API 喂给 NAC，由 NAC 做准入/隔离决策；Aegis 不安装 NAC。
  - **桌管**：Aegis 把合规/风险结果回传桌管，供其做补丁与管控决策；桌管反过来负责推 Aegis。
- **接入中心（控制台）= 集成控制面**：统一列出已集成产品、健康状态、策略映射、告警汇聚；对下全部走 4A / 适配器接口。

一句话："一个端"指**员工终端只新增 Aegis 这一个 agent**；其余能力要么服务端集成、要么由既有桌管/EDR 承担，**推送通道永远归桌管**。

## 四、执行顺序与依赖

1. **A：打标+处置**（#1）— 纯控制台+策略+PG，无外部依赖，先做。
2. **B：风险信号人话化**（#5）— 文档+UI 解释，紧随 A（A 的处置界面正好需要这些解释）。
3. **C：客户端自更新**（#2）— 为后续"推送新 bundle/子模块"打基础，必须在 D/E/F 之前。
4. **D：4A+开源验证集成**（#3）— 你验证候选后，逐个以适配器接入。
5. **E：自定义基线+上游同步+扫描模式**（#4）— 依赖 C 的下发通道。
6. **F：接入中心大改+单端**（#6）— 收口，把 D/E 的集成统一进控制面与单 bundle。

每阶段：本地门禁 → 真机验证 → 提交 → 交付报告；涉及策略/客户端变更走发行级联与签名。
