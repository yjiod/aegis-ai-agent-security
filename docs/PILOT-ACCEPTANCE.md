# 终端治理试点：验收标准与证据

本文定义候选版本和真实试点的通过条件，**不表示当前发行已经通过这些验证**。具体排期、设备清单、负责人和现场证据应保留在受控项目记录中，不提交到公开仓库。

## 范围与产品决策

| 决策 | 验收约束 |
| --- | --- |
| 管理本地 IDE、CLI 和桌面 Agent | macOS、Windows 分别验证；纯网页及云端执行不纳入本地控制承诺 |
| 按实际运行形态识别工具 | 同品牌 CLI、IDE、桌面不能合为一个已通过项；本机 WSL 若使用，按独立本地环境验收 |
| 区分实验室与真实试点 | 候选构建通过实验室用例只说明具备受控试点的证据，不能升级为真实舰队通过 |
| 保留单端原则 | 设备、工具实例、治理资产与引用关系分别计数，避免把工具数量当成探针数量 |
| 先证明再扩大执行 | 观察、隔离环境处置、真实终端处置、扩大范围分别记录放行结果 |
| 所有状态反映真实阶段 | 决定、发布、送达、执行、验证、恢复和风险结论不得互相替代 |
| 尊重共享对象的实际影响 | 影响预览同时包含物理变更对象数与受影响工具实例数；无法精确隔离时不得扩大到未授权对象 |

本地客户端启动远程任务时，界面应明确远程执行不在本地 Agent 的控制范围。检测出风险能力不等于确认恶意，规则严重度也不能替代已经定义并校准的决策置信度。

工具候选及版本登记见[工具覆盖矩阵](TOOL-COVERAGE-MATRIX.md)。本标准补充[开发流程](DEVELOPMENT.md)、[发行流程](RELEASE.md)和[演练手册](CANARY-DRILL-RUNBOOK.md)，不替代仓库现有安全门禁或生产变更审批。

## 最小验收单元

每行至少记录产品、形态、地区版、工具版本、操作系统与架构、原生/WSL 等运行环境、安装作用域及 Aegis 构建。按声明支持的真实组合建立行，不人为生成厂商不支持的组合。

| 能力 | 最低通过证据 |
| --- | --- |
| 工具识别 | 真实安装、版本与多实例正确归属；相同品牌的不同产品形态不误合并 |
| 资产发现 | 找到已声明的用户、项目、插件、企业及显式配置来源，标明来源与解析限制 |
| 治理检测 | 默认参数及模块组合符合声明；目标样本检出，良性样本得到正确结论；双端语义一致 |
| 精确处置 | 目标实际受限，范围与授权一致，其他工具和资产的正常工作用例通过 |
| 恢复与验证 | 撤销本产品的变更并保留期间合法修改；目标、策略版本、验证方法与时间可核对 |
| 告知与持续状态 | 区分通知提交、接收和显示；执行证据有有效期，缺失或过期不会显示为持续健康 |

结果使用 `not_tested`、`passed`、`failed`、`not_applicable`。未实现仍属于未通过，不能改为不适用；不适用需要厂商能力或配置作用域依据。`passed` 必须附环境类别与证据，实验室通过不会自动成为现场通过。

## 必测用户场景

| ID | 场景 | 最低通过条件 |
| --- | --- | --- |
| AC-01 | 工具身份及有效配置来源 | 同机同品牌多形态可区分；正确定位实际生效的用户、项目、插件或显式配置。仅发现一个目录不能宣称完整覆盖 |
| AC-02 | 同名资产与共享资产 | 三个工具中同名不同内容的对象不串判；共享对象保留全部消费者关系，发布前能展示真实影响 |
| AC-03 | 默认策略、模块门控与观察模式 | 关闭可选代码质量检查后，声明的治理检测仍有效；各开关在双端语义一致；观察模式不触发意外处置，正负样本均有结果 |
| AC-04 | 发布、执行和验证失败 | 注入落库失败、发布拒绝、离线、权限不足和回执过期，均不显示已阻断；重试可追踪且幂等；工单关闭不计作已验证修复 |
| AC-05 | 精确处置与跨工具影响 | 一份配置中多个 MCP、多个工具共享程序或网络目标时，只改变授权范围；正常工作、新旧会话分别验证；无法隔离的粒度明确标为限制 |
| AC-06 | 恢复与并发变更 | 新处置不得移动或删除用户文件；旧隔离资产须能按授权恢复到原位置。恢复只撤销本产品的实际变更，保留合法升级、配置与权限变化；记录缺失或冲突不冒充完整恢复 |
| AC-07 | 告知、健康与生命周期 | 安装、升级中断、重启、离线重连、通知失败、退出受管和回滚可验证；多工具同时运行时正常工作；没有新事件不等于保护持续有效 |
| AC-08 | 规模、积压与数据对账 | 稳定负载、同时重连、重复/乱序、大报告、策略下发及并发查询均有结果；接收、重复、拒绝、失败、积压和持久化可对账；真实规模另有证据 |

尤其需要验证：共享文件的读权限限制、共享可执行文件限制、进程终止和网络限制是否影响其他消费者。若控制点无法满足选定范围，不能仅补提示文字后判为精确处置通过。

原状态恢复需考虑权限差量与并发修改。不得假定删除当前拒绝项就能恢复原始权限；权限元数据正确也不能替代实际运行身份的行为验证。[Windows ACL 命令语义](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/icacls)

## 可配置的合成参考负载

以下是测试输入示例，不是部署实绩或已验证容量：

| 变量 | 参考值或定义 |
| --- | --- |
| N：上报客户端 | 200 个合成设备身份 |
| I：工具实例 | 每设备 3 个，合计约 600 个实例 |
| A：唯一治理资产 | 按 Skill/MCP 等实际测试对象统计，不等于工具实例数 |
| R：引用关系 | 工具实例通过配置作用域使用资产的关系；共享资产可以 A=1、R=3 |

单端原则下约 600 个工具实例仍对应约 200 个上报客户端。若每设备每周期提交一份报告，平均报告请求率按 N/周期秒数估算；工具数主要影响扫描成本、报告大小、资产关系与处置影响，不能直接推导为三倍上报 QPS。

至少覆盖三种分布：资产彼此独立；大量共享 Skill/MCP；混合少量大报告设备及突发重连。记录每报告工具数、资产数、引用数、发现数、字节数以及处理时间的分布，不使用三个空工具标签代表三工具真实负载。

合成负载、实验室真机与现场试点分别记录结果。余量测试不代表相同数量的真实终端已经安装或兼容。真实规模按稳定设备身份去重，在线、离线、安装失败、未回报和工具实例数分别列出。

## 放行与证据

| 阶段 | 需要的证据 |
| --- | --- |
| 候选版本实验室验收 | 固定构建、完整发行工件、双端适用用例、默认参数、失败路径、处置/恢复、样本边界及已知缺口 |
| 受控真实试点 | 授权目标、现场安装与回报、告警及恢复责任、真实使用样本；不能借实验室结果预填现场通过 |
| 扩大设备或执行范围 | 上一批结果、误报与业务影响、在线/全量分母、观察窗口、资源开销及恢复证据 |

观察窗口、策略收敛时延、核心操作延迟、资源预算和可用性目标在测试前由项目记录冻结。测得值与目标值分列；无法达到时记录失败，不事后调整口径冒充达标。现场观察从对应批次实际就绪开始，实验室运行时长不替代现场噪声测量。

每条证据至少包含：

| 字段 | 含义 |
| --- | --- |
| `case_id` | 验收用例编号 |
| `build_sha` / `artifact_digest` | 被测提交及发行工件摘要 |
| `environment_kind` | `synthetic`、`laboratory` 或 `field_pilot` |
| `platform` / `tool_version` | 平台、架构、运行形态和工具版本 |
| `sample_profile` | 脱敏或合成样本的来源类别、数量和适用范围 |
| `expected` / `observed` / `result` | 预期、观察结果、通过/失败/未测/不适用 |
| `evidence_ref` / `verified_at` | 受控证据引用及核验时间 |
| `residual_limitations` | 剩余限制、部分覆盖、失败范围及恢复结果 |

同一设备三个工具仅两个通过时，设备应显示部分覆盖；不能用整体绿色状态遮住第三个工具的未知、失败或过期证据。样本集中未发现误伤应连同样本量报告，不推出总体误伤率为零。

公开仓库只保留标准、合成样本与脱敏摘要。实际设备/人员标识、原始配置、访问凭据、客户地址、生产报告、现场排期和非公开安全证据应保留在受控记录中。读取配置时只提取必要字段，不将含认证信息的整份文件送入模型或日志。
