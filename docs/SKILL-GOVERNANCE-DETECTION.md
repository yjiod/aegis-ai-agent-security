# Skill 治理与代码质量开关

Skill 内容治理由 `modules.skill_scan` 和 `skill_rules` 控制。`modules.code_scan`
只控制可选代码质量检查；关闭它不得使已启用的 Skill 治理信号在检测或报告层消失。

当前独立规则为 `prompt_override`、`credential_access`、`context_poisoning`、
`hidden_instruction`。它们检查已发现 Skill 包的声明及支持文件，保留 Skill 资产身份，
不在发现证据中附带原始匹配片段。具体规则仍需在 `skill_rules` 中启用；本变更不改写
已有策略规则清单。出厂文件与控制台新发布策略的规则集合可能不同，应以终端实际加载的
已签名策略为准。

允许目录决定资产准入，不能代替包内容检测。已允许的 Skill 仍执行上述规则；代码扫描
关闭时，报告保留带有 Skill 身份的治理信号，普通项目代码的同名发现仍受代码开关控制。
规则命中是待决策的风险信号，不是任意文本必然恶意的证明，也不代表终端已实际阻断。
控制台抑制、人工例外、自动决策及执行回执仍需按产品验收契约分别完成。

为减少文本误报，独立 Skill 扫描不因仅出现 `memory.md` 文件名而产生上下文投毒信号；
文件开头单个 UTF-8 BOM 作为编码标记处理，内容中间的隐藏控制字符仍检测。规则匹配
不能完整理解引用或否定语境，生产强制策略启用前仍需良性样本评估和影响范围验证。

Windows 补充独立 Skill 包内容遍历：最多 500 个候选文件及有界目录队列，文件读取
受字节上限约束；重解析点不向下遍历，达到上限会报告截断。此处不扩展工具发现根目录，
不证明所有主流工具已覆盖；也不声称解决本地高权限攻击者并发替换文件的全部问题。
已知工具发现、链接边界及真实执行控制点仍需独立验证。

## 验证与发布

`tests/test_skill_governance.py` 使用合成家目录和包，验证不同代码扫描开关/模式下的
检测、真实报告组装、规则关闭、Skill 开关关闭、允许包、BOM、良性文件名引用及资产
身份过滤。报告测试替换硬件身份、真实工具发现和执行边界，不读取真实用户资料。

`scripts/test-skill-governance.ps1` 通过 PowerShell AST 加载仓库中三个指定函数，
仅在新建临时目录运行合成包。不会运行扫描器启动、DPAPI 解密、入网、真实目录发现、
封禁或上报。CI 分别使用原生 Windows ARM64/x64 的 Windows PowerShell 验证这些函数。

本批是源代码候选，`release.json` 标记待发布变更。现存原生二进制未因源码更新自动重建，
不能把原有二进制引用当作包含本修复。正式客户端发布前必须统一版本号、重建相应平台
包和二进制、生成更新清单并完成签名与安装/回滚验证；本批未宣称发布就绪。
